# Профиль 10

Чат-бот и мини-приложение в MAX, которые показывают девятикласснику, **какие
направления подготовки в вузах останутся ему доступны при каждом профиле его
школы, а какие закроются** — и какой один предмет нужно добрать, чтобы вернуть
потерянное.

Трек «Образовательные решения».

---

## 1. Назначение решения

**Проблема.** Ученик 9 класса в ситуации записи в профильный 10 класс хочет
выбрать профиль так, чтобы не потерять интересные ему специальности, но
связка «профиль → углублённые предметы → ЕГЭ → перечень вступительных
испытаний → направление подготовки» нигде не собрана вместе. Из-за этого
решение принимается по критериям «где друзья» и «где меньше математики», а
цена ошибки выясняется в 11 классе, когда менять профиль поздно.

**Что делает продукт.** За 3–5 минут в чате MAX ученик отмечает интересные ему
направления подготовки и получает сравнение всех профилей своей школы: сколько
его направлений закрывает каждый профиль, какие именно закрываются и почему
(какого предмета не хватает), и что нужно добрать элективом, чтобы вернуть
максимум. Карточку с разбором можно показать родителям и классному
руководителю; к сроку подачи заявления приходит напоминание.

**Второй пользователь — школа.** Классный руководитель или завуч видит
обезличенный агрегат по классу: какие направления интересны ученикам, какие
из них не закрывает ни один существующий профиль и добавление какого одного
электива даст наибольший эффект.

## 2. Основной пользовательский сценарий

1. Ученик открывает чат-бота «Профиль 10» в MAX и нажимает «Начать».
2. Вводит код класса, который дал классный руководитель (например, `9A-114`).
   Бот подтягивает профили именно его школы и срок подачи заявления.
3. Отвечает, какой профиль рассматривает сейчас (нужно, чтобы потом измерить,
   изменился ли выбор после расчёта).
4. Нажимает «Открыть подбор» — запускается мини-приложение.
5. Отмечает до 8 интересных направлений подготовки (каталог с поиском и
   группировкой) и нажимает «Сравнить профили».
6. Видит профили, отсортированные по доле закрытых направлений. По каждому:
   разбор направлений (доступно всё / часть вузов / недоступно), причина
   недоступности и подсказка «что спросить в школе».
7. Может отметить предметы, которые готов добрать самостоятельно или
   элективом, — все профили пересчитываются.
8. Выбирает профиль и нажимает «Отправить разбор в чат». Карточка приходит в
   чат MAX, там же ставится напоминание о сроке подачи заявления.

Роль школы: тот же адрес мини-приложения с `?role=curator`, вход по коду
куратора (например, `KUR-114-9A`).

## 3. Состав и архитектура решения

```
        MAX (мобильный и веб-клиент)
        ├── чат-бот ──────── Bot API (long polling) ─────┐
        └── мини-приложение (HTTPS) ──── REST /api ──┐   │
                                                     ▼   ▼
   ┌────────────────────────┐   служебный    ┌──────────────────┐
   │  bot (Python)          │◄──контур──────►│  api (FastAPI)   │
   │  · диалог и кнопки     │  очередь       │  · справочники   │
   │  · доставка карточек   │  outbox        │  · расчётное ядро│
   │  · напоминания         │                │  · анкеты, агрегат│
   └────────────────────────┘                │  · статика мини-  │
                                             │    приложения     │
                                             └─────────┬────────┘
                                                       │
                                            SQLite (том profil10-data)
                                            data/*.json (справочники)
```

| Компонент | Технологии | Роль |
|---|---|---|
| `api/` | Python 3.11, FastAPI, SQLite | Справочники, расчёт, анкеты, агрегат для школы, раздача мини-приложения, очередь сообщений |
| `bot/` | Python 3.11, requests | Диалог в MAX, запуск мини-приложения, доставка карточек и напоминаний |
| `miniapp/` | React 18, Vite | Каталог направлений, сравнение профилей, экран классного руководителя |
| `data/` | JSON | Демонстрационные справочники |
| `tools/mockmax/` | FastAPI | Стенд-эмулятор Bot API MAX для локальной проверки |

Ключевые решения:

* **Бот не хранит состояние.** Владелец данных — API; бот после перезапуска
  продолжает начатый сценарий, потому что запрашивает состояние заново.
* **Очередь `outbox` вместо входящего порта у бота.** Мини-приложение просит
  API отправить карточку, API кладёт её в очередь, бот забирает и доставляет.
  Перезапуск бота не теряет сообщения, напоминание переживает рестарт.
* **Тексты сообщений живут в API** (`api/app/cards.py`) — одна точка правды.
* **Платформенные детали MAX изолированы** в `bot/bot/max_api.py`.
* **Точная арифметика.** Доли считаются в `fractions.Fraction`, проценты
  округляются через `round()`; ядро (`api/app/engine.py`) не зависит от вебa
  и покрыто тестами.

## 4. Запуск

Требуется Docker с плагином Compose.

```bash
cp .env.example .env     # заполнить MAX_BOT_TOKEN, APP_SECRET, INTERNAL_KEY, PUBLIC_BASE_URL
docker compose up --build
```

Поднимутся два локальных компонента: `api` (порт 8080) и `bot` (long polling к
MAX). Мини-приложение собирается внутри образа `api` и раздаётся по пути `/app/`.

### Запуск без доступа к платформе MAX (проверка сценария на стенде)

```bash
docker compose --env-file .env.demo --profile demo up --build
```

Дополнительно поднимается `maxstand` — эмулятор Bot API MAX на порту 8081.
Бот работает с ним вместо `https://botapi.max.ru`, и весь сценарий, включая
доставку карточки и напоминание, проходится целиком локально.

### Остановка и повторный запуск

```bash
docker compose down                 # остановить, данные в томе сохранятся
docker compose up                   # запустить снова (пересборка не нужна)
docker compose down -v              # остановить и удалить данные анкет
docker compose restart bot          # перезапустить только бота
docker compose logs -f api bot      # смотреть логи
```

Состояние хранится в томе `profil10-data`. После `down` без `-v` анкеты,
напоминания и агрегат по классу сохраняются.

## 5. Переменные окружения

Полный список с комментариями — в `.env.example`. Обязательные:

| Переменная | Кому | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | bot | Токен чат-бота MAX. Выдаёт организатор/владелец бота |
| `APP_SECRET` | api | Секрет подписи токенов мини-приложения (случайная строка ≥32 символов) |
| `INTERNAL_KEY` | api, bot | Ключ служебного контура «бот → API» |
| `PUBLIC_BASE_URL` | api | Публичный **HTTPS**-адрес, по которому MAX открывает мини-приложение |

Необязательные: `MAX_API_BASE` (по умолчанию `https://botapi.max.ru`),
`MINIAPP_BUTTON_TYPE` (`link`), `API_PORT` (8080), `STAND_PORT` (8081),
`MIN_AGGREGATE` (5), `MAX_FIELDS` (8), `REMINDER_DAYS_BEFORE` (3),
`REMINDER_DEMO_DELAY` (0), `CORS_ORIGINS` (`*`), `POLL_TIMEOUT` (30),
`LOG_LEVEL` (`INFO`).

Секреты в репозитории отсутствуют. `.env` в `.gitignore`; значения в
`.env.demo` — заведомо нерабочие и принимаются только стендом.

## 8. Внешние сервисы и интеграции

| Интеграция | Статус в MVP | Что потребуется после MVP |
|---|---|---|
| **Bot API MAX** (`https://botapi.max.ru`) | Реальная. Единственная внешняя зависимость. Работает по токену, выданному организатором | — |
| **Мини-приложение MAX** | Реальная: запускается из чат-бота по HTTPS-ссылке | Уточнить по актуальной документации тип кнопки запуска (`MINIAPP_BUTTON_TYPE`) и добавить проверку параметров запуска MAX в дополнение к подписи токена |
| **Справочник вступительных испытаний** | **Модельные данные** (`data/fields.json`) | Официальная выгрузка перечня вступительных испытаний и сверка с правилами приёма вузов региона |
| **Профили, классы и сроки школы** | **Демонстрационные данные** (`data/schools.json`) | Ввод куратором через интерфейс школы либо загрузка из региональной информационной системы |

Собственных внешних API решение не вызывает. LLM не используется: расчёт
детерминированный и объяснимый.

## 9. Работа с данными

**Что откуда берётся.** Продукт всегда разделяет три вида информации, и это
видно пользователю:

* *факт из справочника* — какие вступительные испытания требует направление;
* *расчёт продукта* — доля закрытых направлений, причина недоступности,
  минимальное дополнение предметов;
* *рекомендация* — «что спросить в школе». Она не выдаётся за требование.

В каждом ответе API есть блок `data` с версией справочников и пометкой
`demo_data`, а в интерфейсе и в карточке — оговорка, что расчёт информационный
и не заменяет правила приёма вуза и решение школы.

**Персональные данные.** Пользователи сценария — несовершеннолетние, поэтому
MVP не собирает ФИО, контакты, оценки и возраст. Хранится: идентификатор
пользователя MAX, код класса, отмеченные направления, исходный и выбранный
профиль. Агрегат для школы обезличен и открывается только при `MIN_AGGREGATE`
(по умолчанию 5) заполненных анкетах — по нему нельзя восстановить ответ
конкретного ученика. Доступ ученика к своей анкете — по токену с подписью
HMAC-SHA256 и сроком жизни; доступ школы — по отдельному коду куратора,
токен привязан к конкретному классу.

**Тестовые данные.** Все справочники в `data/` — демонстрационные, это явно
указано в самих файлах (`kind`, `source_note`) и в ответе `GET /api/meta`.

Демо-коды для проверки:

| Что | Значение |
|---|---|
| Классы | `9A-114`, `9B-114` (Лицей № 114, Казань), `9A-ALM7` (СОШ № 7, Альметьевск) |
| Коды кураторов | `KUR-114-9A`, `KUR-114-9B`, `KUR-ALM7-9A` |

Класс `9B-114` намеренно оставлен пустым — на нём видно, как работает порог
k-анонимности. Школа `9A-ALM7` имеет всего два профиля — на ней видно, как
выглядит отчёт «школа не закрывает запросы учеников».

Чтобы очистить накопленные анкеты: `docker compose down -v`.

## 10. Пошаговый сценарий проверки

### Автоматически

```bash
docker compose --env-file .env.demo --profile demo up --build -d
pip install -r requirements-dev.txt

python3 -m pytest tests -q                       # ядро расчёта и API (26 тестов)
python3 tools/api_contract_check.py --base http://localhost:8080   # проверки из DATA-API.yaml
INTERNAL_KEY=demo-only-not-a-secret-1111111111 REMINDER_DEMO_DELAY=20 \
  python3 tools/scenario_check.py                # сквозной сценарий через чат-бота
```

Ожидаемый результат: `26 passed`, `пройдено 14, не пройдено 0`,
`Итог: успешно 35, неуспешно 0`.

### Вручную, в MAX

1. Открыть чат-бота, нажать «Начать» → бот здоровается и просит код класса.
2. Отправить `9A-114` → бот показывает школу, срок подачи и пять профилей.
3. Нажать «Технологический» → бот присылает кнопку «Открыть подбор».
4. Открыть мини-приложение, отметить: `09.00.00`, `38.00.00`, `40.00.00`,
   `31.00.00`, `45.00.00`. Нажать «Сравнить профили».
5. Проверить расчёт: технологический профиль закрывает **2 из 5 (40,0 %)**;
   юриспруденция недоступна — «не хватает: обществознание».
6. Нажать чип «+ Обществознание» → технологический становится **3 из 5**.
7. Нажать «Технологический» в блоке «Отправить разбор в чат» → карточка
   приходит в чат MAX, ставится напоминание о сроке.
8. Открыть `<PUBLIC_BASE_URL>/app/?role=curator`, ввести `KUR-114-9B` →
   сводка закрыта: анкет меньше порога. Ввести `KUR-114-9A` → сводка открыта.

### Вручную, через API

```bash
curl -s localhost:8080/api/health
curl -s localhost:8080/api/classes/9A-114
curl -s -X POST localhost:8080/api/match -H 'content-type: application/json' \
  -d '{"class_code":"9A-114","fields":["09.00.00","31.00.00","40.00.00"]}'
```

Документация: `http://localhost:8080/docs`, контракт — `openapi.yaml`,
обязательные проверки — `DATA-API.yaml`.

## 11. Примеры ожидаемого поведения

| Действие | Ожидаемое поведение |
|---|---|
| Ввод `9A-114` | Школа, срок подачи заявления, список профилей с углублёнными предметами |
| Ввод `ааа` или неизвестного кода | Бот не падает: подсказывает формат кода класса, диалог продолжается |
| Расчёт по 5 направлениям для технологического профиля | `available=2`, `total=5`, `percent=40.0`, `fraction="2/5"` |
| Юриспруденция при технологическом профиле | `status="none"`, `gap_required=["soc"]` — «не хватает обществознания» |
| Клиническая медицина при естественно-научном профиле | `status="full"` — закрыты все варианты испытаний |
| ИВТ при естественно-научном профиле | `status="partial"` — доступна часть вузов (закрыта химия, но не информатика и физика) |
| Подсказка для технологического профиля | «добрать обществознание и иностранный язык → вернётся 3 направления» |
| Выбор 9 направлений | HTTP 422, `error="too_many_fields"`, понятное сообщение и подсказка |
| Чужой или испорченный токен | HTTP 401/403, предложение открыть мини-приложение из бота заново |
| Запрос агрегата без токена куратора | HTTP 401 |
| Агрегат по классу с 3 анкетами при пороге 5 | `status="insufficient_data"`, разрезы не выдаются |
| Недоступность API при работе бота | Бот отвечает «сервис недоступен», повторяет попытки с нарастающей паузой, диалог не теряется |
| Перезапуск бота на середине сценария | Сценарий продолжается: состояние хранится в API |

## 12. Известные ограничения

1. **Справочник вступительных испытаний — модельный.** Построен по структуре
   перечня вступительных испытаний, но не является официальной выгрузкой.
   Конкретный предмет из списка выбирает вуз в своих правилах приёма, поэтому
   продукт различает «доступны все вузы направления» и «доступна часть вузов».
2. **Ключевое допущение расчёта.** Формально ученик вправе сдавать любой ЕГЭ
   независимо от профиля. Модель считает предмет закрытым, если он не
   изучается углублённо и не добран. Допущение показано пользователю, а чипы
   «готов добрать предмет» позволяют пересчитать без него.
3. **Данные школ демонстрационные**: профили, коды классов и сроки вымышлены.
4. **Тип кнопки запуска мини-приложения** вынесен в `MINIAPP_BUTTON_TYPE`:
   по умолчанию это обычная ссылка, которая работает и в мобильной, и в
   веб-версии MAX. Документация MAX обновляется — параметр сверяется перед
   запуском.
5. **Валидация параметров запуска мини-приложения MAX** не реализована:
   доступ защищён подписанным токеном из бота. Для пилота проверку
   launch-параметров MAX нужно добавить дополнительно.
6. **SQLite** рассчитан на масштаб класса и школы. Для региона схема
   переносится на PostgreSQL без изменения логики.
7. **Продукт не даёт психологических и профориентационных заключений**: он
   отвечает только на вопрос о доступности направлений и всегда адресует
   сложные случаи классному руководителю.

