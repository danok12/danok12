# Пайплайн построения vision-language датасета из робототехнических траекторий

Решение задачи AIJ Robotics: из сырых эпизодов (LeRobot v3 + эгоцентрические
видео) автоматически строится ShareGPT JSONL для дообучения VLM-backbone
SmolVLM2, который затем используется в SmolVLA.

```text
LeRobot v3 / видео ──► кинематический разбор ──► генераторы сигналов ──► балансировка ──► annotations.jsonl
   parquet, mp4        схват, фазы, события        19 типов заданий        квоты и дедуп      + images/
```

Ключевая идея: **разметка выводится из самих траекторий, а не из внешней модели**.
Состояния и действия робота дают то, чего нет в тексте инструкции — момент
захвата и отпускания, фазу выполнения, прогресс, застой и сорвавшийся захват.
Поэтому пайплайн работает офлайн, не требует ни весов сторонних моделей, ни
ручной разметки, и при одинаковых входах даёт побитово одинаковый результат.

---

## 1. Быстрый старт

```bash
pip install -r requirements.txt

# самопроверка на синтетическом эпизоде: генерация + валидация + детерминизм
./src/tools/run_smoke.sh

# рабочий прогон
python generate_dataset.py \
    --input /data/raw \
    --output /output/annotations.jsonl \
    --config config.yaml
```

Полезные флаги: `--limit-episodes N` (отладка), `--num-workers N`, `--max-samples N`,
`--seed N`, `--dry-run` (статистика без записи), `--log-level DEBUG`.

Результат рядом с `annotations.jsonl`:

| Файл | Что внутри |
|------|-----------|
| `annotations.jsonl` | обучающая выборка в формате ShareGPT |
| `annotations.val.jsonl` | валидационная выборка (разбиение по эпизодам) |
| `annotations.meta.jsonl` | провенанс каждого примера: источник, эпизод, кадр, тип задания, шаблон |
| `annotations.stats.json` | доли типов заданий, форматов, источников, баланс букв в MCQ |
| `annotations.manifest.json` | полный конфиг, его отпечаток, seed, перечень источников |
| `images/<источник>/…` | извлечённые кадры, на которые ссылается JSONL |

## 2. Входные данные

`--input` — каталог, внутри которого лежат распакованные датасеты. Каталог с
`meta/info.json` распознаётся как LeRobot v3, каталог с видеофайлами — как
эгоцентрический источник:

```text
/data/raw/
├── BridgeData2_LeRobot_v3/     meta/info.json, data/…, videos/…
├── fractal20220817_data_lerobot/
├── language_table_lerobot_v30/
└── Egocentric-100K/            *.mp4
```

Поддерживаются оба варианта хранения кадров LeRobot v3: изображения внутри
parquet (`dtype: image`) и видео `mp4` рядом (`dtype: video` + `video_path`);
во втором случае кадр берётся по метке времени эпизода через PyAV.

Если автообнаружение не подходит, источники задаются явно в `config.yaml`:

```yaml
input:
  discover: false
  sources:
    - {name: bridge, type: lerobot, path: /data/raw/BridgeData2_LeRobot_v3, weight: 1.0}
    - {name: ego, type: video_folder, path: /data/raw/Egocentric-100K}
```

## 3. Что попадает в датасет

21 генератор; каждый ответ выводится из проверяемого сигнала траектории.

| Генератор | Вопрос модели | Откуда берётся правильный ответ |
|-----------|---------------|--------------------------------|
| `gripper_state` | открыт ли схват, держит ли объект | нормированное раскрытие губок + события захвата |
| `phase` | стадия манипуляции | сегментация эпизода по событиям схвата и высоте |
| `progress` | какая доля задачи выполнена | положение кадра в эпизоде |
| `subtask` | текущая и следующая подзадача | фаза × декомпозиция инструкции |
| `instruction_decomp` | разложить инструкцию на шаги | лексический разбор инструкции |
| `instruction_check` | соответствует ли сцена инструкции | контрастные пары со «чужой» инструкцией |
| `object_role` | какой объект и куда | объект и адресат из инструкции |
| `spatial_relation` | где в кадре манипулятор | разностная локализация подвижной области |
| `grounding_box` / `grounding_point` | рамка / точка в пикселях | то же, с порогом уверенности |
| `temporal_order` | какой кадр раньше | порядок кадров в эпизоде |
| `progress_compare` | где прогресс больше | индексы кадров |
| `frame_transition` | что изменилось между кадрами | дельты схвата, высоты, положения в кадре, смена фазы |
| `multiview_match` | сняты ли виды одновременно | согласованные и рассинхронизированные пары камер |
| `view_role` | какой вид наручный | автоопределение наручной камеры |
| `episode_summary` | пересказ траектории по 3 кадрам | последовательность фаз |
| `failure_diagnosis` | что пошло не так | застой движения, схват сомкнулся вхолостую |
| `recovery_instruction` | как восстановиться | корректирующий шаг для найденного сбоя |
| `scene_caption` | описание сцены | сборка из всех проверенных признаков |
| `ego_temporal_order`, `ego_transition` | порядок кадров, смещение обзора | индексы кадров, фазовая корреляция |

Пример строки (одиночный кадр, множественный выбор):

```json
{"messages": [{"role": "user", "content": "<image>\nWhat subtask is the robot currently performing?\nInstruction: pick up the alphabet soup and place it in the basket\n\nA. move the gripper above the alphabet soup\nB. close the gripper on the alphabet soup\nC. lift the alphabet soup off the surface\nD. withdraw the arm\nAnswer with the option's letter from the given choices directly."}, {"role": "assistant", "content": "B"}], "images": ["images/bridge/000123_image_00042.jpg"]}
```

Пример с двумя кадрами (temporal/multi-view задания используют по одному
`<image>` на каждое изображение — ровно столько, сколько путей в `images`):

```json
{"messages": [{"role": "user", "content": "Image 1: <image>\nImage 2: <image>\nWhat changed between the first and the second frame?\nInstruction: put the cream cheese in the bowl"}, {"role": "assistant", "content": "Between the two frames the gripper closed on the cream cheese, the arm moved upward, the end effector shifted up and to the right in the image, the robot went from reaching toward the object to lifting the grasped object. The overall task is: put the cream cheese in the bowl."}], "images": ["images/bridge/000123_image_00031.jpg", "images/bridge/000123_image_00044.jpg"]}
```

### Почему именно такой состав

* **Формат ответа обучается вместе с содержанием.** Семь из восьми оценочных
  наборов (ERQA, MMMU ×3, BLINK, CrossPoint, EmbSpatial) — задания с выбором
  ответа. Доля MCQ задаётся `language.mcq_share`, директивы повторяют
  формулировки lmms-eval, а буква правильного ответа выравнивается по позициям
  (`mcq_balance_letters`), чтобы модель не выучила позиционное смещение.
* **Пространственные и мультивидовые задания** (`spatial_relation`, `grounding_*`,
  `multiview_match`, `view_role`) прицельно поддерживают EmbSpatial, BLINK и
  CrossPoint.
* **Прогресс, подзадачи, сбои и восстановление** — это то, чего нет в исходной
  разметке эпизодов и что напрямую нужно VLA-части: закрытый бенчмарк включает
  ошибки выполнения и сценарии восстановления.
* **Против переобучения формой**: пулы перефразировок, квота на шаблон
  (`language.max_share_per_template`), квоты на тип задания, ограничение числа
  примеров с эпизода и дедупликация кадров по перцептивному хешу.

## 4. Как устроен пайплайн

| Модуль | Ответственность |
|--------|-----------------|
| `src/lerobot.py` | чтение LeRobot v3: `meta/info.json`, эпизоды, parquet, кадры из parquet или mp4 |
| `src/kinematics.py` | схема `state`/`action`, калибровка схвата, события, фазы, прогресс |
| `src/vision.py` | ресайз, фильтры качества, dHash, разностная локализация движения |
| `src/frames.py` | выбор кадров (ключевые события + равномерная сетка), запись, определение наручной камеры |
| `src/language.py` | разбор инструкции, декомпозиция на шаги, соответствие фаза → шаг |
| `src/templates.py` | пулы формулировок, сборка MCQ, формат ответа |
| `src/tasks.py` | 21 генератор обучающих сигналов |
| `src/sources.py` | обнаружение источников, обработка одного эпизода |
| `src/pipeline.py` | параллельный прогон, сбор, балансировка, запись |
| `src/writer.py` | квоты, дедупликация, разбиение train/val, статистика |
| `src/validate.py` | проверка итогового JSONL |
| `src/tools/` | валидатор JSONL, самопроверка, сборка архива решения |
| `src/tests/` | синтетический фикстур и тесты |

Всё, что не входит в пятёрку обязательных файлов архива, лежит внутри `src/` —
структура корня совпадает с эталонным `submission.zip`.

Три момента, на которых держится качество разметки:

1. **Калибровка схвата по данным.** Ориентация канала («больше — шире раскрыт»
   или наоборот) определяется предположением «в начале эпизода схват открыт», а
   порог «открыт/закрыт» — методом Оцу по распределению раскрытий всего
   источника. Фиксированные пороги на разных воплощениях (LIBERO, WidowX, RT-1)
   дают ложные срабатывания, калибровка — нет.
2. **Сегментация без разметки.** Переходы открыт→закрыт→открыт с гистерезисом
   дают моменты захвата и отпускания; профиль высоты отделяет подъём от переноса
   и подведения; окна почти нулевой скорости дают застой; смыкание губок плотнее,
   чем позволил бы объект, — сорвавшийся захват.
3. **Локализация без детекторов.** Подвижная область находится разностью кадров
   (порог по перцентилю, морфология, связные компоненты) с оценкой уверенности;
   примеры ниже `grounding.min_confidence` не попадают в датасет. Для наручной
   камеры разностный метод отключён — там движется весь кадр.

## 5. Конфигурация

Все ручки — в `config.yaml` с комментариями. Чаще всего меняют:

| Параметр | Смысл |
|----------|-------|
| `budget.max_samples` | размер итогового датасета |
| `budget.max_episodes_per_source` | сколько эпизодов брать с источника |
| `budget.max_samples_per_episode`, `max_frames_per_episode` | плотность выборки по эпизоду |
| `tasks.<имя>.weight` | доля типа задания в итоге |
| `language.mcq_share` | доля заданий с выбором ответа |
| `grounding.min_confidence` | строгость отбора пространственных примеров |
| `output.frame_long_side` | разрешение сохраняемых кадров |
| `runtime.num_workers` | число процессов |

Отпечаток конфига (`config_fingerprint`) пишется в `stats.json` и `manifest.json` —
по нему видно, каким именно конфигом собран датасет.

Опциональная секция `captioner` позволяет обогатить датасет описаниями от
локальной VLM через OpenAI-совместимый endpoint. По умолчанию она выключена:
базовый пайплайн полностью детерминирован и не зависит от сторонних весов.

## 6. Воспроизводимость

* Единственный источник случайности — `seed`; все выборки делаются
  детерминированными хешами от `(seed, ключ примера)`, а не от глобального RNG,
  поэтому результат не зависит от числа процессов и порядка обработки эпизодов.
* Источники, эпизоды и генераторы обходятся в отсортированном порядке.
* Проверка входит в `./src/tools/run_smoke.sh`: два прогона с 1 и 4 воркерами дают
  побитово одинаковый `annotations.jsonl`.

```bash
python -m pytest src/tests -q  # 13 тестов: разбор инструкций, события, сквозной прогон, mp4-вариант
```

Фикстур собирается скриптом `src/tests/make_fixture.py`: скриптованная траектория
«подвод → захват → подъём → перенос → опускание → отпускание → отвод» с
согласованными состояниями и отрисованными кадрами, плюс сценарии со срывом
захвата и застоем. Ключ `--video` кладёт кадры в mp4 — так проверяется путь
чтения Bridge и Fractal (тест сверяет кадр из mp4 с тем же кадром из parquet).

## 7. Соответствие требованиям задачи

| Требование | Как выполнено |
|-----------|---------------|
| Стандартный запуск `--input/--output/--config` | `generate_dataset.py` |
| Работа без интернета | нет сетевых вызовов; веса моделей не используются |
| Без ручной разметки | вся разметка выводится из траекторий программно |
| Воспроизводимость при фиксированных входах и сиде | детерминированные хеши, тест в smoke |
| Формат ShareGPT | `messages` + `images`, число `<image>` равно числу путей; проверяется `src/tools/validate_annotations.py` |
| Не датасет действий | в ответах нет векторов действий и дискретизированных траекторий; состояния и действия используются только как источник разметки на естественном языке. Проверяется тестом `test_no_action_vector_leakage` |
| Исходные изображения не копируются | в `images/` сохраняются только извлечённые кадры, нужные конкретным примерам (отдельный кадр parquet/mp4 нельзя адресовать путём) |

**Контрольный запуск у организатора.** Генератор работает прямо в образе из
`participant.zip`, ничего доустанавливать не нужно: `pyarrow`, `av`,
`opencv-python-headless`, `PyYAML`, `numpy` и `pillow` там уже стоят, и их версии
попадают в диапазоны `requirements.txt`. Проверено на Python 3.12 (интерпретатор
образа): тесты проходят, а `annotations.jsonl` побитово совпадает с результатом
на Python 3.11.

## 8. Дальнейшие шаги до submission

Пайплайн закрывает первую стадию — построение датасета. Дальше используется
репозиторий участника (`participant.zip`), обучение идёт на ваших GPU:

```bash
# 1. датасет
python generate_dataset.py --input /data/raw --output /data/vlm/train.jsonl --config config.yaml

# 2. SFT SmolVLM2 + обучение action-эксперта SmolVLA (участниковский пайплайн)
#    configs/participant.yaml:
#      vlm.data_path: /data/vlm/train.jsonl
#      vlm.eval_data_path: /data/vlm/train.val.jsonl
#      vlm.media_dir: /data/vlm
./scripts/run_pipeline.sh configs/participant.yaml

# 3. сборка архива решения
./src/tools/make_submission.sh \
    --annotations /data/vlm/train.jsonl \
    --smolvlm2 runs/<run>/submission/smolvlm2 \
    --action-expert runs/<run>/submission/action_expert \
    --output submission.zip
```

Скрипт кладёт в корень архива ровно то, что требует организатор, проверяет
`annotations.jsonl` и предупреждает о недостающих файлах чекпойнтов:

```text
submission.zip
├── README.md
├── requirements.txt
├── generate_dataset.py
├── config.yaml
├── annotations.jsonl
├── src/
├── smolvlm2/         config.json, model.safetensors, generation_config.json,
│                     processor_config.json, tokenizer_config.json, tokenizer.json,
│                     chat_template.jinja
└── action_expert/    config.json, model.safetensors, train_config.json,
                      policy_preprocessor.json, policy_postprocessor.json,
                      policy_{pre,post}processor_step_*.safetensors
```

В эталонном архиве `smolvlm2/` весит ≈ 2.03 ГБ, `action_expert/` ≈ 1.42 ГБ —
это веса в fp32. Если ваши каталоги вышли примерно вдвое легче, чекпойнт
сохранён в bf16; стоит сверить с протоколом обучения перед отправкой.

Относительные пути в JSONL резолвятся от `vlm.media_dir`, поэтому каталог
`images/` должен лежать рядом с JSONL (либо `media_dir` указывается явно).

## 9. Ограничения

* Разностная локализация рассчитана на неподвижную камеру; для наручной и
  эгоцентрической она отключена, пространственные задания для них не строятся.
* Разбор инструкций — лексический и рассчитан на короткие английские императивы
  (именно такие в Bridge, Fractal, Language Table и LIBERO). Незнакомая
  конструкция не ломает прогон: эпизод получает общие шаги без объекта и адресата.
* Признак «эпизод успешен» берётся из того, что открытые датасеты состоят из
  демонстраций; отдельные сбойные фрагменты выявляются по застою и холостому
  смыканию схвата, а не по внешней метке успеха.
* Память воркера ≈ размер одного data-файла источника (в LeRobot v3 — до 100 МБ),
  это стоит учитывать при выборе `runtime.num_workers`.
* Диск: кадры сохраняются как JPEG с длинной стороной `output.frame_long_side`.
  Один кадр обслуживает несколько заданий — на прогонах выходит ≈0.3 кадра на
  пример, так что `budget.max_samples: 400000` — это порядка 100–150 тыс. кадров
  (≈5–10 ГБ при 512 px на реальных снимках). Кадры, не попавшие в итоговую
  выборку после балансировки, удаляются автоматически
  (`output.prune_unused_frames`).
