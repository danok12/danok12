# Сайт журнала ДЗ

Обычный сайт на GitHub Pages: открывается в любом браузере, без аккаунта Claude и вообще без
регистрации. Данные лежат рядом, в `data.json`, в этом же репозитории.

Адрес сайта: **https://danok12.github.io/danok12/**

Адрес именно такой, с папкой: корневой `danok12.github.io` получают репозитории, названные
`danok12.github.io`, а этот называется `danok12`, поэтому сайт проектный.

## Три роли

| Кто | Что делает |
|---|---|
| Любой, кто знает адрес | видит замок с полем пароля |
| Тот, кому вы сказали пароль | входит и читает журнал: кому что задано и до какого числа |
| Вы | вдобавок правите: кнопки, сохранение в репозиторий |

## Пароль — это ключ шифрования, а не проверка

Пароль нигде не проверяется и нигде не хранится. Им **расшифровывается сам файл**: в репозитории
лежит шифротекст (AES-GCM 256, ключ из пароля через PBKDF2-SHA256, 310 000 итераций, своя соль и
nonce на каждое сохранение). Кто скачает `data.json` напрямую, увидит base64 и ничего больше.

Отсюда следствия:

- **пароль из трёх букв защитой не будет** — файл публичный, перебор идёт офлайн. Берите фразу;
- **забытый пароль не восстанавливается.** Данные зашифрованы им, запасного ключа нет;
- смена пароля — это перешифровка файла: задали новый в настройках и нажали «Сохранить»;
- пароль держится в памяти вкладки (`sessionStorage`), закрыли вкладку — спросит снова.

## Чтобы кнопки работали (только для вас)

Статический сайт сам по себе писать никуда не может — записывать в репозиторий должен кто-то с
правом. Поэтому один раз на каждом своём устройстве:

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token;
2. Repository access: **Only select repositories** → `danok12/danok12`;
3. Permissions → Repository permissions → **Contents: Read and write**;
4. скопировать токен, на сайте открыть **⚙** → вставить в «Токен GitHub» → «Сохранить токен».

После этого появляются кнопки и «Сохранить». Токен лежит в `localStorage` этого браузера и никуда
не отправляется, кроме api.github.com. На чужом компьютере его вводить не нужно; отозвать можно в
любой момент на той же странице GitHub.

Сохранение делает коммит в `main`, после чего workflow пересобирает сайт — у остальных изменения
появятся через минуту-две, не мгновенно.

## Что где лежит

```
site/index.html   приложение целиком: замок, таблица, диалоги, шифрование, запись через GitHub API
site/data.json    база учеников: {"enc":true, kdf, iv, ct} после первого сохранения с паролем
.github/workflows/pages.yml   сборка и публикация при каждом изменении site/
```

Структура расшифрованных данных:

```js
{ students: [ {
  id, name, group,
  hw: { title, due, issued, status: "issued|done", doneAt, note } | null,
  done: [ { title, due, status, doneAt } ]   // последние 15
} ] }
```

## Первый запуск

1. влить ветку в `main` — workflow сам включит Pages и выложит сайт;
   если не получится, включить вручную: Settings → Pages → Source: **GitHub Actions**;
2. открыть https://danok12.github.io/danok12/ — журнал пока не зашифрован и пуст, показаны строки-примеры;
3. вставить токен через **⚙**;
4. там же задать пароль (от 8 символов) и нажать «Сохранить» — файл станет зашифрованным;
5. добавить учеников и снова «Сохранить»;
6. сообщить пароль тем, кому нужен доступ.

Порядок важен: пароль задать **до** того, как в журнале появятся фамилии.

## От поисковиков закрыто

В `index.html` стоит `<meta name="robots" content="noindex, nofollow">` — по ссылке сайт
открывается у всех, но в выдачу Google не попадает. Если индексация нужна, уберите эту строку;
с фамилиями учеников делать этого не стоит.
