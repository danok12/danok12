# Репозиторий учебных материалов

Здесь не код, а **материалы для занятий** (репетиторство: математика, линейная алгебра, подготовка к ЕГЭ). Рабочий язык — русский, включая коммиты и описания PR.

## Структура

```
lessons/<тема>/
  PLAN.md      план занятия для преподавателя, с ответами и методическими заметками
  ZADACHI.md   условия задач для печати ученику, без ответов
  OTVETY.md    ответы и решения
  *.pdf        собранные версии: отдельно преподавателю и отдельно ученику
```

Существующие темы:
- `lessons/1.5-obratnaya-matrica/` — обратная матрица (§1.5 учебника линейной алгебры) + тренажёр с каталогом ошибок
- `lessons/ege-baza-14/` — задание 14 базового ЕГЭ, «вычисления и преобразования»

Вне `lessons/`:
- `zhurnal-dz/` — журнал домашних заданий (кому выдано, что сдать, до какого числа); исходник страницы-артефакта

## Правила работы с материалами

1. **Каждый числовой ответ пересчитывать программой**, не в уме. Точная арифметика: `fractions.Fraction`, а не float. Перед выдачей материала прогонять все задачи скриптом и сверять с текстом.
   Осторожно с выводом: `int(8.999999999)` даёт 8. Округлять через `round(v, 6)`, а не усекать.
2. **Задачи придумывать свои.** Не переписывать условия из учебников и КИМ. Тот же тип, свои числа.
3. **Держаться обозначений источника ученика.** Если в его учебнике `|A|` и `A'` — писать так, а не `det A` и `Aᵗ`, и давать таблицу соответствия с другими обозначениями.
4. **Разбирать типовые ошибки отдельным блоком**: как выглядит, откуда берётся, как поймать, задание-противоядие. Формат «найди ошибку в готовом неверном решении» работает лучше обычных задач.
5. **Версия ученику — без ответов и без учительских комментариев** (заметки преподавателю, «как читать диагностику» и прочее убирать, а не только спойлеры).

## Публикация страниц (Artifact)

Страницы занятий публикуются как Artifact с общей вёрсткой: петролевая палитра, `Spectral` для заголовков, `Source Sans 3` для текста, `JetBrains Mono` для формул; матрицы — CSS-сетка со скобками через `::before/::after`; ответы под `<details>`. Новую тему верстать в том же стиле — это серия.

## Сборка PDF

Chromium уже установлен, качать ничего не нужно:

```bash
CH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome
"$CH" --headless --disable-gpu --no-sandbox --no-pdf-header-footer \
  --virtual-time-budget=8000 --print-to-pdf="out.pdf" "file://$PWD/print.html"
```

Печатную копию HTML готовить так (иначе PDF выйдет чёрным и без ответов):

1. убрать `<link>` на Google Fonts — сети нет, рендер повиснет; локальные фолбэки печатаются нормально;
2. вырезать блоки `@media (prefers-color-scheme:dark)` и `:root[data-theme="dark"]` — иначе тёмная тема;
3. заменить `<details>` на `<details open>` — иначе ответы не попадут в PDF;
4. добавить print-CSS: `@page{margin:14mm 12mm}`, `break-inside:avoid` на карточки, матрицы и строки таблиц, `break-after:avoid` на заголовки.

`pdftoppm` в контейнере нет, поэтому проверять вёрстку скриншотом: `sed 's/@media print{/@media all{/'` и `--screenshot` в Chromium.

## Git

- Работать в ветке, указанной в задании сессии. **В `main` не пушить без явного разрешения.**
- PDF коммитить вместе с исходниками: контейнер сессии временный, а файлы должны остаться.
